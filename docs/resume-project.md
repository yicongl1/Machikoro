## 1. 30 秒介绍

MachiKoro 是我们的一门 C++ 面向对象课程项目。我们用 C++14 实现了一个支持 1~N 名玩家和 AI 的控制台桌游，包含 15 种建筑、4 种地标、五色卡牌结算、市场购买和胜负判定。

我在团队中主要参与核心代码开发与调试，覆盖卡牌体系、回合结算、购买流程、AI 和输入处理等模块中的部分工作。项目最终可以完整运行，并配套了 UML、课程笔记和演示视频。

## 5. 面试口述提纲

### 背景

课程要求用 C++ 实现一个完整的小型系统。我们选择 MachiKoro 桌游，因为它规则清晰，但卡牌类型多、结算顺序复杂，适合练习面向对象设计。

### 任务

实现一个可玩的控制台版本：

- 15 种普通建筑 + 4 种地标
- 红/蓝/绿/紫四阶段收入结算
- 市场购买、胜负判定
- 支持多名玩家和 AI

### 我的工作

参与核心代码开发与调试，覆盖卡牌体系、回合结算、购买流程、AI 和输入处理等模块中的部分工作。具体可展开为：

- 卡牌继承体系与多态结算
- 购买流程与边界校验
- AI 决策
- 输入解析与文档整理

> 如果记不清具体模块，保留第一句即可；面试时不要展开没有把握的细节。

### 难点与解决

1. **多态结算的上下文设计**
   `action(Bank* p1, Bank* p2, Card* c1, Card* c2, int val)` 用两个 `Bank*` 表达“谁付谁”，用 `c1` 非空表示 Shopping Mall 加成，用 `val` 表示倍率数量。

2. **购买流程的返回值语义**
   早期版本把“金币数 / 卡槽号”混在同一个返回值里，容易白拿卡或越界；重构后用 `PurchaseCode` 枚举区分 `NO_PURCHASE` / `YELLOW_PURCHASE` / 普通卡槽，并统一为“先校验、后扣钱”。

3. **卡槽索引失效**
   购买成功后 `erase` 会导致下标变化，因此重新打印市场，并基于实际 `slot.size()` 做边界检查。

4. **AI 与人类共用回合流程**
   通过 `isBot` 分支 + “买得起、非重复紫卡”的合法动作候选集，避免 AI 产生非法输入。

5. **输入健壮性**
   使用 `normalize` + `parse_int` + `getline` 统一处理空白、EOF、空行、越界和非法命令，避免 `cin >>` 与 `getline` 混用。

### 结果

- 项目可编译、可运行，支持人类与 AI 混合对局
- 修复了购买、结算、输入处理中的 10+ 处逻辑/边界问题
- 配套 UML 类图、课程笔记、演示视频和旧版原型归档

### 反思

如果重做，我会：

- 把视图与游戏逻辑拆开（Game / View / Controller）
- 使用智能指针管理卡牌和玩家对象
- 为核心结算逻辑补单元测试
- 把卡牌数值配置化，减少硬编码
